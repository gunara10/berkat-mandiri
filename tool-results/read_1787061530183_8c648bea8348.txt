   147→   647→   647→### ⚠️ Cover Content Overflow Prevention (Mandatory)
   148→   648→   648→
   149→   649→   649→1. Cover section page margin is 0; total content height ≤ 15638 twips (1200 twips safety margin for cross-engine compatibility — MS Office renders large fonts taller than calculated).
   150→   650→   650→2. Color block Table `height` must use `rule: "exact"` (never `"atLeast"`).
   151→   651→   651→3. Each recipe code includes height budget annotations — verify during generation.
   152→   652→   652→4. **`verticalAlign` must always be `"top"`**. Never use `"center"` or `"bottom"` in exact-height rows — content will be clipped or overflow. Use `spacing.before` on the first paragraph for vertical positioning.
   153→   653→   653→5. **Title font size MUST be dynamically calculated via `calcTitleLayout()`** (see below). Never hardcode font sizes above 40pt for cover titles. Every recipe MUST call `calcTitleLayout()` before building title paragraphs.
   154→   654→   654→6. **Never use `margins.top`/`margins.bottom` for vertical positioning inside exact-height cells**: Cell margins reduce available height unpredictably across MS Office and WPS. Use `spacing.before` on the first paragraph instead. Only `margins.left`/`margins.right` are safe.
   155→   655→   655→7. **Dynamic spacing is mandatory**: Use `calcCoverSpacing()` to compute `spacing.before` values dynamically based on content element count and title line count. Never use fixed large spacing values (e.g., `before: 4500`) that assume a specific title length.
   156→   656→   656→8. **Cover must be a single-page section**: The cover section must produce exactly ONE page. If content overflows to a second page, it means the height budget is violated. Common overflow causes and fixes:
   157→   657→   657→   - Title font too large → use `calcTitleLayout()` to auto-reduce
   158→   658→   658→   - Too many meta lines → reduce font size or remove less important lines
   159→   659→   659→   - Fixed `spacing.before` values too large → use `calcCoverSpacing()` for dynamic values
   160→   660→   660→   - Subtitle + English label + meta lines combined exceed budget → calculate total and reduce spacing
   161→   661→   661→9. **Cover wrapper table MUST use explicit `allNoBorders`**: The outer 16838 wrapper table and ALL nested tables inside the cover MUST set borders to NONE explicitly. Never rely on docx-js default borders (`single/auto/sz=4`). Default borders add ~8 twips per edge, which causes MS Office to calculate a total height slightly exceeding 16838 → content overflows to a blank page 2. WPS is more lenient but MS Office is strict. **This is the #1 cause of "blank page 2 in MS Office but not in WPS".**
   162→   662→   662→
   163→   663→   663→```js
   164→   664→   664→// ✅ MANDATORY: Define and use allNoBorders for every cover table
   165→   665→   665→const NB = { style: BorderStyle.NONE, size: 0, color: "FFFFFF" };
   166→   666→   666→const noBorders = { top: NB, bottom: NB, left: NB, right: NB };
   167→   667→   667→const allNoBorders = { top: NB, bottom: NB, left: NB, right: NB,
   168→   668→   668→                       insideHorizontal: NB, insideVertical: NB };
   169→   669→   669→
   170→   670→   670→new Table({
   171→   671→   671→  borders: allNoBorders,  // ← MANDATORY on every cover table
   172→   672→   672→  // ...
   173→   673→   673→});
   174→   674→   674→```
   175→   675→   675→
   176→   676→   676→10. **Decorative lines MUST use paragraph borders, NEVER text characters**: Horizontal decorative lines (accent strips, dividers, frame edges) must be implemented with `paragraph border.top` or `border.bottom` — never with text characters like `───`, `━━━`, `═══`, or `——————`. Character-drawn lines render at inconsistent widths across MS Office and WPS (font metrics differ), causing lines to appear truncated or misaligned. Paragraph borders render pixel-perfect in both engines and their width is controlled precisely via `indent.left` / `indent.right`.
   177→   677→   677→
   178→   678→   678→```js
   179→   679→   679→// ✅ Correct — paragraph border (R2 style thick accent rule)
   180→   680→   680→new Paragraph({
   181→   681→   681→  indent: { left: 1000, right: 1000 },
   182→   682→   682→  border: { top: { style: BorderStyle.SINGLE, size: 18, color: P.accent, space: 20 } },
   183→   683→   683→  children: [],
   184→   684→   684→})
   185→   685→   685→
   186→   686→   686→// ❌ FORBIDDEN — text character line (renders inconsistently)
   187→   687→   687→new Paragraph({
   188→   688→   688→  children: [new TextRun({ text: "───────────────", color: P.accent })]
   189→   689→   689→})
   190→   690→   690→```
   191→   691→   691→9. **Post-generation overflow check (mandatory)**: After building cover children, estimate total height:
   192→   692→   692→   ```js
   193→   693→   693→   function estimateCoverHeight(elements) {
   194→   694→   694→     let total = 0;
   195→   695→   695→     for (const el of elements) {
   196→   696→   696→       if (el instanceof Table) {
   197→   697→   697→         // Sum row heights (exact rows) or estimate 400 twips per row
   198→   698→   698→         const rows = el.root?.[0]?.rows || [];
   199→   699→   699→         for (const row of rows) {
   200→   700→   700→           total += row.height?.value || 400;
   201→   701→   701→         }
   202→   702→   702→       } else if (el instanceof Paragraph) {
   203→   703→   703→         const fontSize = el.root?.[0]?.size || 24; // half-pts
   204→   704→   704→         // ★ Use pt * 11.5 (= half-pt * 10 * 1.15) for accurate single-spacing estimate
   205→   705→   705→         const lineHeight = Math.max(fontSize * 11.5, 276); // min 276 (default 12pt)
   206→   706→   706→         const spacingBefore = el.spacing?.before || 0;
   207→   707→   707→         const spacingAfter = el.spacing?.after || 0;
   208→   708→   708→         total += lineHeight + spacingBefore + spacingAfter;
   209→   709→   709→       }
   210→   710→   710→     }
   211→   711→   711→     return total;
   212→   712→   712→   }
   213→   713→   713→   // ★ Target: estimateCoverHeight(coverChildren) < 15638 (16838 - 1200 safety)
   214→   714→   714→   ```

   218→   718→   718→### ⚠️ Cover Title Layout — calcTitleLayout() (Mandatory for ALL Recipes)
   219→   719→   719→
   220→   720→   720→**Every cover recipe MUST use `calcTitleLayout()` to determine title font size and line breaks.** Hardcoding font sizes or passing the full title as a single TextRun is FORBIDDEN.
   221→   721→   721→
   222→   722→   722→**Every paragraph with font size > body text MUST set explicit line spacing** to prevent top clipping:
   223→   723→   723→```js
   224→   724→   724→// ★ MANDATORY: prevent inherited small line spacing from clipping large fonts
   225→   725→   725→spacing: { line: Math.ceil(titlePt * 23), lineRule: "atLeast", after: 100 }
   226→   726→   726→// Example: 36pt → line: 828; 44pt → line: 1012
   227→   727→   727→```
   228→   728→   728→Without this, the paragraph inherits body text line spacing (e.g., 560tw), which is shorter than the font height → top of characters gets clipped.
   229→   729→   729→
   230→   730→   730→```js
   231→   731→   731→/**
   232→   732→   732→ * Calculate safe font size and smart line breaks for cover titles.
   233→   733→   733→ * MUST be called by every recipe before building title paragraphs.
   234→   734→   734→ *
   235→   735→   735→ * @param {string}  title          Full title string
   236→   736→   736→ * @param {number}  maxWidthTwips  Available width for title text (twips, after subtracting margins/padding)
   237→   737→   737→ * @param {number}  preferredPt    Desired max font size in pt (default 40)
   238→   738→   738→ * @param {number}  minPt          Minimum allowed font size in pt (default 24)
   239→   739→   739→ * @returns {{ titlePt: number, titleLines: string[] }}
   240→   740→   740→ */
   241→   741→   741→function calcTitleLayout(title, maxWidthTwips, preferredPt = 40, minPt = 24) {
   242→   742→   742→  // Each CJK character width ≈ pt × 20 twips
   243→   743→   743→  const charWidth = (pt) => pt * 20;
   244→   744→   744→  const charsPerLine = (pt) => Math.floor(maxWidthTwips / charWidth(pt));
   245→   745→   745→
   246→   746→   746→  // Try from preferredPt downward until title fits in ≤ 3 lines
   247→   747→   747→  let titlePt = preferredPt;
   248→   748→   748→  let lines;
   249→   749→   749→  while (titlePt >= minPt) {
   250→   750→   750→    const cpl = charsPerLine(titlePt);
   251→   751→   751→    if (cpl < 2) { titlePt -= 2; continue; }
   252→   752→   752→    lines = splitTitleLines(title, cpl);
   253→   753→   753→    if (lines.length <= 3) break;
   254→   754→   754→    titlePt -= 2;
   255→   755→   755→  }
   256→   756→   756→
   257→   757→   757→  // If still > 3 lines at minPt, force 3 lines
   258→   758→   758→  if (!lines || lines.length > 3) {
   259→   759→   759→    const cpl = charsPerLine(minPt);
   260→   760→   760→    lines = splitTitleLines(title, cpl);
   261→   761→   761→    titlePt = minPt;
   262→   762→   762→  }
   263→   763→   763→
   264→   764→   764→  return { titlePt, titleLines: lines };
   265→   765→   765→}
   266→   766→   766→
   267→   767→   767→/**
   268→   768→   768→ * Smart Chinese title line-breaking — breaks at semantic boundaries, never mid-word.
   269→   769→   769→ *
   270→   770→   770→ * Rules:
   271→   771→   771→ * 1. Prefer breaking after particles, punctuation, connectors, underscores, spaces
   272→   772→   772→ * 2. Never split a compound word (e.g., "管理规范" must not become "管理规" + "范")
   273→   773→   773→ * 3. No single-character orphan on the last line — merge into previous line
   274→   774→   774→ * 4. If no good break point found within 60-130% of charsPerLine, break at charsPerLine
   275→   775→   775→ *
   276→   776→   776→ * @param {string} title        Full title string
   277→   777→   777→ * @param {number} charsPerLine Max characters per line at current font size
   278→   778→   778→ * @returns {string[]}          Array of line strings
   279→   779→   779→ */
   280→   780→   780→function splitTitleLines(title, charsPerLine) {
   281→   781→   781→  if (title.length <= charsPerLine) return [title];
   282→   782→   782→
   283→   783→   783→  // Characters that are safe break points (break AFTER these)
   284→   784→   784→  const breakAfter = new Set([
   285→   785→   785→    ...'，。、；：！？',              // CJK punctuation
   286→   786→   786→    ...'的与和及之在于为',            // CJK particles/prepositions
   287→   787→   787→    ...'-_—–·/',                     // connectors
   288→   788→   788→    ...' \t',                         // whitespace
   289→   789→   789→  ]);
   290→   790→   790→
   291→   791→   791→  const lines = [];
   292→   792→   792→  let remaining = title;
   293→   793→   793→
   294→   794→   794→  while (remaining.length > charsPerLine) {
   295→   795→   795→    let breakAt = -1;
   296→   796→   796→
   297→   797→   797→    // Search backward from charsPerLine to 60% for a break point
   298→   798→   798→    for (let i = charsPerLine; i >= Math.floor(charsPerLine * 0.6); i--) {
   299→   799→   799→      if (i < remaining.length && breakAfter.has(remaining[i - 1])) {
   300→   800→   800→        breakAt = i;
   301→   801→   801→        break;
   302→   802→   802→      }
   303→   803→   803→    }
   304→   804→   804→
   305→   805→   805→    // If not found, search forward up to 130%
   306→   806→   806→    if (breakAt === -1) {
   307→   807→   807→      const limit = Math.min(remaining.length, Math.ceil(charsPerLine * 1.3));
   308→   808→   808→      for (let i = charsPerLine + 1; i < limit; i++) {
   309→   809→   809→        if (breakAfter.has(remaining[i - 1])) {
   310→   810→   810→          breakAt = i;
   311→   811→   811→          break;
   312→   812→   812→        }
   313→   813→   813→      }
   314→   814→   814→    }
   315→   815→   815→
   316→   816→   816→    // Last resort: break at charsPerLine, but avoid splitting compound CJK words
   317→   817→   817→    if (breakAt === -1) {
   318→   818→   818→      breakAt = charsPerLine;
   319→   819→   819→      // If both chars at the break boundary are CJK (likely a compound word),
   320→   820→   820→      // step back 1 char to keep the word together
   321→   821→   821→      const prevChar = remaining[breakAt - 1];
   322→   822→   822→      const nextChar = remaining[breakAt];

   327→   827→   827→      }

   330→   830→   830→    lines.push(remaining.slice(0, breakAt).trim());
   331→   831→   831→    remaining = remaining.slice(breakAt).trim();

   333→   833→   833→  if (remaining) lines.push(remaining);
   334→   834→   834→
   335→   835→   835→  // Prevent single-character orphan on last line — merge into previous
   336→   836→   836→  if (lines.length > 1 && lines[lines.length - 1].length <= 2) {
   337→   837→   837→    const last = lines.pop();
   338→   838→   838→    lines[lines.length - 1] += last;

   344→   844→   844→/**
   345→   845→   845→ * Calculate dynamic spacing values for cover elements to fit within page height.
   346→   846→   846→ *
   347→   847→   847→ * @param {object} params
   348→   848→   848→ * @param {number} params.titleLineCount   Number of title lines
   349→   849→   849→ * @param {number} params.titlePt          Title font size in pt
   350→   850→   850→ * @param {boolean} params.hasSubtitle     Whether subtitle exists
   351→   851→   851→ * @param {boolean} params.hasEnglishLabel Whether English label exists
   352→   852→   852→ * @param {number} params.metaLineCount    Number of meta info lines
   353→   853→   853→ * @param {number} params.fixedHeight      Sum of fixed-height elements (color strips, accent bars, footer) in twips
   354→   854→   854→ * @param {number} params.pageHeight       Total page height in twips (default 16838)
   355→   855→   855→ * @returns {{ topSpacing, midSpacing, bottomSpacing }}  Spacing values in twips
   356→   856→   856→ */
   357→   857→   857→function calcCoverSpacing(params) {
   358→   858→   858→  const {
   359→   859→   859→    titleLineCount = 1, titlePt = 36, hasSubtitle = false,
   360→   860→   860→    hasEnglishLabel = false, metaLineCount = 0,
   361→   861→   861→    fixedHeight = 800, pageHeight = 16838,
   362→   862→   862→    marginTop = 0, marginBottom = 0,   // ★ NEW: pass actual section margins
   363→   863→   863→  } = params;
   364→   864→   864→
   365→   865→   865→  // ★ Safety margin: 1200 twips (cross-engine: MS Office renders large fonts
   366→   866→   866→  // taller than calculated; extra 400tw buffer prevents footer clipping)
   367→   867→   867→  const SAFETY = 1200;
   368→   868→   868→  // ★ Subtract page margins from available height (cover section may have margins)
   369→   869→   869→  const usableHeight = pageHeight - marginTop - marginBottom - SAFETY;
   370→   870→   870→
   371→   871→   871→  // ★ Accurate height estimation per element:
   372→   872→   872→  const titleHeight = titleLineCount * (titlePt * 23 + 200);
   373→   873→   873→  const subtitleHeight = hasSubtitle ? (12 * 23 + 600) : 0;
   374→   874→   874→  const englishLabelHeight = hasEnglishLabel ? (9 * 23 + 600) : 0;
   375→   875→   875→  const metaHeight = metaLineCount * (10 * 23 + 100);
   376→   876→   876→
   377→   877→   877→  // ★ Account for implicit paragraph heights:
   378→   878→   878→  const implicitParaHeight = 3 * 300;
   379→   879→   879→
   380→   880→   880→  const contentHeight = titleHeight + subtitleHeight + englishLabelHeight +
   381→   881→   881→                        metaHeight + fixedHeight + implicitParaHeight;
   382→   882→   882→
   383→   883→   883→  const remainingSpace = usableHeight - contentHeight;
   384→   884→   884→  const safeRemaining = Math.max(remainingSpace, 400);
   385→   885→   885→
   386→   886→   886→  // ★ Footer protection: bottomSpacing must be ≥ FOOTER_MIN to prevent
   387→   887→   887→  // footer + accent line from being clipped at the cell bottom edge
   388→   888→   888→  const FOOTER_MIN = 800;
   389→   889→   889→  const rawTop = Math.floor(safeRemaining * 0.45);
   390→   890→   890→  const rawBottom = Math.floor(safeRemaining * 0.45);
   391→   891→   891→  const bottomSpacing = Math.max(rawBottom, FOOTER_MIN);
   392→   892→   892→  const topSpacing = Math.max(rawTop - Math.max(0, FOOTER_MIN - rawBottom), 400);
   393→   893→   893→  const midSpacing = Math.max(safeRemaining - topSpacing - bottomSpacing, 0);
   394→   894→   894→
   395→   895→   895→  return { topSpacing, midSpacing, bottomSpacing };
   396→   896→   896→}

   426→   926→   926→### ⚠️ CRITICAL — Cover Section Non-Negotiables (ALL Recipes)
   427→   927→   927→
   428→   928→   928→These 3 properties are MANDATORY for every cover implementation (R1–R7). Omitting ANY of them causes cover layout failure:
   429→   929→   929→
   430→   930→   930→1. **Cover section margin = 0**: The cover MUST be in its own section with `page.margin: { top: 0, bottom: 0, left: 0, right: 0 }`. Non-zero margins shrink the wrapper away from page edges → white gaps around the cover ("cover not filling the page"). This is the #1 cause of broken cover layouts.
   431→   931→   931→
   432→   932→   932→2. **Wrapper row exact height**: The outer wrapper table row MUST set `height: { value: 16838, rule: "exact" }`. Without this, content overflow pushes to page 2, or insufficient content leaves bottom whitespace.
   433→   933→   933→
   434→   934→   934→3. **Wrapper table borders = allNoBorders**: MUST explicitly set `borders: allNoBorders`. Default docx-js borders add ~8 twips per edge. MS Office includes border thickness in exact-height calculation → total exceeds 16838 → blank page 2 (WPS is lenient, MS Office is strict).
